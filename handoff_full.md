### quest-control-system
Коммерческий проект для действующей квест-комнаты (по знакомству, без договора). 4 программы на Python/Pygame: управление 16 замками через ESP32/Arduino по HTTP, освещение по зонам (через **COM-порт, pyserial** — это в README упомянуто отдельно), две интерактивные панели для игроков. Многопоточность (UI не блокируется), мягкая деградация при отвале железа, EEPROM+watchdog в прошивках, конфиги отдельно от кода, сборка в exe. Есть раздел «Что я сделал бы иначе».

Замечания, которые мы находили: импорты разбросаны по всему файлу (строки 84, 946, 1051…), `import sys, os, pygame` в одну строку. Переписывать не стали — проект сдан. Но в новых проектах: все импорты сверху, по одному на строку.

### reminder-bot
Бот напоминаний о повторяющихся делах. Сделан целиком в этом чате.

Архитектура: `bot.py` (хендлеры, FSM-диалог), `database.py` (SQLite), `scheduler_logic.py` (календарные расчёты), `reminder_scheduler.py` (планирование и отправка), `keyboards.py`, `states.py`.

Ключевые решения:
- **Хранится срок, а не моменты напоминаний** — моменты вычисляются из срока и настроек окна
- `add_months` берёт минимум между исходным днём и последним днём месяца: 31 января + месяц = 28 февраля
- Моменты создаются с `tzinfo` пользователя через `zoneinfo`, планировщик работает в UTC
- `SQLAlchemyJobStore(url="sqlite:///jobs.db")` — задачи на диске, переживают перезапуск
- `misfire_grace_time=3600` — пропущенные за простой не летят пачкой
- `cycle_finished()` — если все напоминания цикла прошли, при возобновлении срок переносится на следующий период
- FSM с валидацией на каждом шаге: дата в прошлом, дни вне 0–30, кривое время

### Steam-endpoint-parser
Парсер цен CS2, два способа сбора данных.

- JSON-эндпоинт `priceoverview`: цена, медиана, объём продаж
- HTML-страница листинга: цены по всем состояниям сразу (Factory New, StatTrak, сувенирные)

Технические ловушки, которые там разобраны и описаны в README:
- **Запятая в цене — десятичная (`379,86`), в объёме — разделитель тысяч (`133,216`).** Одинаковый символ, противоположный смысл. Поэтому две функции: `parse_price` и `parse_volume`. Иначе 133 тысячи превращаются в 133
- Steam разделяет разряды **неразрывным пробелом `\xa0`**, обычный `.replace(" ", "")` его не ловит
- Страница листинга на SSR-фреймворке, данные в `window.SSR.loaderData` — JSON внутри JSON. Извлекается через `json.JSONDecoder().raw_decode()`, **не регуляркой** (на вложенных структурах регулярка обрывается)
- Steam отдаёт SSR-пакет **не всегда** — на один и тот же URL иногда приходит урезанная версия. Поэтому повторные попытки и поиск нужного блока перебором по содержимому, а не по индексу
- Обработка 429 с растущей паузой (60/120/180), обработка `requests.exceptions.RequestException`
- Выгрузка в Excel через openpyxl: два листа, `freeze_panes`, числовые форматы `#,##0.00` и `#,##0`, имя файла с датой и временем

### crypto-rate-bot
Телеграм-бот курсов криптовалют: CoinGecko API, inline-кнопки с callback, SQLite для избранных монет, деплой на VPS как systemd-сервис с `Restart=always`. Из резюме убран (напоминалка перекрывает по навыкам), но на GitHub остаётся.

### ballistic-trajectory
C++17 + SFML + CMake, ~5300 строк. Рунге-Кутта 4-го порядка по вектору состояния, экспоненциальная модель плотности атмосферы, параллельный расчёт аналитического решения. Режим «заготовки» (материал+форма → Cd, площадь, масса), 5 интерактивных графиков. Учебная практика по ТЗ.

Замечание: `src/App*.inc`, подключаемые в `main.cpp` — один большой файл, механически разрезанный. Раздельной компиляции нет. Для практики сойдёт, но на собеседовании спросят.

## 8. Правила работы с заказами (выработаны на практике)

**Всегда читать полный текст ТЗ до решения.** Короткие превью систематически скрывают реальный объём. Обожглись на: «настройка 1С» (оказалось программирование бухгалтерских проводок), «перепрошить радиотерминалы» (оказалось прошивка Android-устройств удалённо), «консультация по amoCRM» (нужен эксперт по конкретному инструменту, а не программист).

**Проверять, не закрыт ли заказ:** если вместо «Предложить услугу» стоит «Оставить отзыв» / «Исполнитель определён» — откликаться некуда.

**Смотреть на цифры заказчика:**
- Процент найма: 0% при 5+ проектах — размещает и не нанимает
- 60%+ и много проектов — реальный заказчик
- 50+ предложений — почти безнадёжно, 100+ — точно
- «Сделано более N покупок» — хороший признак

**Структура отклика, которая работает:**
1. Что понял из задачи своими словами (показывает, что читал)
2. Технический момент, который остальные не заметят — главное отличие
3. Что сделаю списком
4. Цена и срок без «обсудим»
5. Один вопрос по существу
6. Упоминание, что код открыт в профиле, и честно про отсутствие отзывов

**Не брать:**
- Обход капчи, антибот-защиты, региональных блокировок
- Userbot (Telethon/Pyrogram) — блокируют аккаунт **заказчика**, и виноват буду я
- Перехват дефицитных ресурсов: слоты записи (визы, техосмотр), чужие заказы в такси
- Сбор персональных данных, базы «недобросовестных» людей
- Скрытый источник: «адрес сайта дам в ЛС» при копеечном бюджете
- Копирование чужого контента на свой сайт
- Читерство в играх, обход блокировок операторов
- Автоматические платежи от чужого имени
- Чужие стеки — уважать фильтр заказчика («откликаться только с опытом amoCRM»)

**Законная альтернатива userbot:** у публичных Telegram-каналов есть веб-версия `t.me/s/имя_канала` — обычная HTML-страница, парсится напрямую через requests + BeautifulSoup. Это аргумент, который сильно выделяет отклик: остальные либо предлагают userbot, либо молчат.

**Красные флаги (из моего services.md):**
- «Сделай сначала, потом заплачу»
- «ТЗ потом, начинай»
- Работа в обход биржи на первых заказах
- Требуют доступы к чужим аккаунтам (root-пароль — просить отдельного пользователя с sudo)
- Обещают «дальше будет много работы, поэтому сейчас дёшево»
- Намёки на обмен отзывами («оставлю хорошую характеристику, ты понял о чём я») — за это банят аккаунт

**Правила работы (мои, из services.md):**
1. Получить описание. Непонятно — спросить, не гадать
2. Написать своими словами, что будет сделано, получить «да»
3. Назвать цену и срок. **Срок × 2 от собственной оценки**
4. Не начинать без согласованного объёма
5. Показывать промежуточный результат
6. Новая хотелка = отдельная строка в смете: «Да, это можно, это доработка — плюс X ₽ и день к сроку»
7. Не соглашаться на «это же мелочь» больше одного раза
8. Сдать: код + инструкция + видео/скриншот работы
9. Вежливо попросить отзыв
10. Записать реальное время работы для калибровки

**Когда поднимать цены:** 5 отзывов → +30%, 10 отзывов → рыночная.

## 10. Мои грабли

| Симптом | Причина |
|---|---|
| `Missing dependencies for SOCKS support`, обрыв SSH `port 22`, `getaddrinfo failed` для googleapis.com | **VPN.** Ломает pip, SSH, Steam. Но для Google API наоборот может быть нужен — проверять в обе стороны |
| Steam Market отдаёт `429 Too Many Requests` | Лимит частоты (~20 запросов/мин). Не долбить повторно — каждая попытка продлевает. Ждать несколько минут |
| `ImportError: cannot import name 'getattr_static' from 'inspect'` | Свой файл назван как стандартный модуль. Никогда не называть `inspect.py`, `json.py`, `types.py`, `random.py`, `email.py` |
| `FileNotFoundError` на файл, который лежит в папке | Windows дописал второе расширение: `credentials.json.json`. Включить показ расширений |
| venv не работает после переноса папки | В venv абсолютные пути. `rmdir /s /q venv`, пересоздать, `pip install -r requirements.txt` |
| `pip install` ставит не то | `beautifulsoup4` → импорт `bs4`; `python-dotenv` → импорт `dotenv` |
| `git add .` затянул venv | `.gitignore` сохранён как `.gitignore.txt` или в UTF-16. Проверять `dir /a` |
| `git add` падает с `does not have a commit checked out` | Внутри папки осталась вложенная папка от неудачного клона |
| Пакет встал не туда | Забыл активировать venv. Проверять `(venv)` в строке |
| `curl` к api.telegram.org зависает | Российский сервер — нужен зарубежный VPS |
| VS Code подчёркивает `import requests` | Выбран не тот интерпретатор. `Ctrl+Shift+P` → `Python: Select Interpreter` → из venv. На запуск не влияет |

## 13. Отдельно: cs2-trade-bot

Приватный проект арбитражного бота для CS2-скинов, делаю с Claude Code. Построены слои `core/` и `storage/`, 265 тестов. Архитектурные решения: все деньги в Decimal, USD как единица учёта, составные ключи идентичности предмета, FeeSchedule для тарифов, «неопределённость → отказ от сделки», таблица trade_cycles (кошельки Steam неконвертируемы).

Заблокирован: cs.market API возвращает `classid`/`instanceid` вместо `market_hash_name`, котировки не сопоставляются. Steam-коллектор упёрся в IP-баны. PriceEmpire отклонён по цене относительно капитала (~$500).

**Решение принято: заморозить.** Не ведёт к цели — дохода нет, портфолио нет (репозиторий приватный), а времени съедает много. Обнаруженный структурный спред 50%+ между Steam и внешними площадками объясняется неконвертируемостью Steam-кошелька, а не рыночной неэффективностью — то есть арбитражить его нельзя.

Ценность: учебный полигон (Decimal-арифметика, SQLAlchemy, Alembic, доменное моделирование, 265 тестов) и потенциальное портфолио, если открыть и вычистить секреты.
